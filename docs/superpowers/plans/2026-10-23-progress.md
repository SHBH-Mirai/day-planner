# Progress (weekly review + streaks) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Week view that shows where this week's time went and the current streaks.

**Architecture:**
- A `listRange` repository call feeds pure domain functions (`weekReview`, `streaks`) in `src/domain/progress.ts`.
- A `WeekView` component renders them.
- `TodayView` adds a fourth switch segment.
- No flow or SharePoint change.

**Tech Stack:** React 19, TypeScript, Vitest 5 + React Testing Library (IST), motion `m.*`.

**Spec:** `docs/superpowers/specs/2026-10-23-progress-design.md`

## Global Constraints
- Week = Monday–Sunday local time. Streak lookback = 28 days. `breaks` is never a streak category.
- Copy, exact:
  - "This week"
  - "Focus", "Done", "Skipped"
  - "vs last week", "Same as last week"
  - "Loading your week…", "Couldn't load your week.", "Retry"
  - "N-day streak"
  - "No streak yet. Tick a task done today to start one."
- Existing tests stay unchanged. `npm test`, `npm run lint`, `npx tsc -b` and `npm run build` pass before each commit.
- Public repo wording rules apply. Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus
1. **A week crossing a month or year boundary.** `weekStart` must use calendar maths, not 7-day millisecond steps around midnight. → Test in Task 2.
2. **Today with nothing done yet.** The streak must not drop to 0 until the day is over. → Test in Task 2.
3. **Tasks with no `actualStart`/`actualEnd` that are done.** They count at their planned length, via `spentMinutes`. → Test in Task 2.
4. **An empty 28 days.** The Week view still renders the tiles at 0, the "No streak yet" text and no category bar. → Test in Task 3.
5. **The load fails.** The error and Retry show, and Retry reloads. → Test in Task 3.

### Task 1: `listRange` in the repositories
**Files:** `src/storage/TaskRepository.ts`, `src/storage/InMemoryTaskRepository.ts`, `src/storage/SharePointTaskRepository.ts`; tests in `src/storage/repositoryContract.ts` (appended).
**Produces:** `listRange(from: Date, days: number): Promise<Task[]>`, which returns tasks starting from local midnight of `from` for `days` days, sorted by start.
- [ ] Contract test: three days of tasks plus one just outside. `listRange(day1, 2)` returns only the first two days, in start order. `listRange(day1, 1)` equals `listForDay(day1)`.
- [ ] RED, then implement. SharePoint: generalise the `listForDay` query to a from/to range, and make `listForDay(day)` call `listRange(day, 1)`. In-memory: filter and sort.
- [ ] GREEN; commit `feat(storage): list tasks over a range of days`.

### Task 2: Domain — week review and streaks
**Files:** create `src/domain/progress.ts` and `src/domain/progress.test.ts`.
**Produces:**
- `weekStart(day: Date): Date`
- `weekReview(tasks: Task[], today: Date): WeekReview` (shape in the spec)
- `streaks(tasks: Task[], today: Date, lookbackDays?: number): Streaks`
- `STREAK_LOOKBACK_DAYS = 28`
- [ ] Tests:
  - `weekStart` for Thu 2026-10-22 → Mon 2026-10-19; Mon 2026-10-19 maps to itself; Sun 2026-11-01 → Mon 2026-10-26, which crosses a month.
  - `weekReview`:
    - `days.length` is 7 and starts on Monday
    - days after today are `future`
    - doneMin and plannedMin per day match `dayTotals`
    - `perCategoryDone` counts only done tasks, and a done task without Started counts its planned length
    - `lastWeekDoneMin` covers only last Monday up to the same weekday
  - `streaks`:
    - none → `{ days: 0, capped: false, byCategory: [] }`
    - done on Mon, Tue, Wed and nothing done on Thu (today) → 3
    - a gap on Tue → 1
    - done every day for 28 days → `{ days: 28, capped: true }`
    - Content on 3 days and Breaks on 5 → byCategory `[{ youtube, 3 }]`
    - a 1-day category run isn't listed
- [ ] RED, then implement, then GREEN; commit `feat(domain): weekly review and streaks`.
