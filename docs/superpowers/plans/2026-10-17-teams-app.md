# Day Planner in Teams Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Run Day Planner as a Teams personal app, signing in through nested app authentication (NAA), with the browser version unchanged.

**Architecture:** A host detector decides at startup whether we run in Teams or a browser. In Teams, MSAL is created with `createNestablePublicClientApplication`, and interactive sign-in uses popups. In a browser, everything stays as it is now (redirect). A static `teams-app/` package (manifest plus icons) is zipped and uploaded by Shubh.

**Tech Stack:** existing app + `@microsoft/teams-js` (approved 2026-10-17).

**Spec:** `docs/superpowers/specs/2026-10-17-teams-app-design.md`

## Global Constraints
- Browser behaviour is unchanged. Every existing test passes untouched; new behaviour comes through optional parameters whose defaults keep today's behaviour.
- NAA config: `auth.supportsNestedAppAuth: true`; initialise TeamsJS before MSAL; interactive calls in Teams are popups (`loginPopup`, `acquireTokenPopup`).
- Host detection timeout: 1500 ms.
- Teams package: personal static tab `entityId: "today"`, `contentUrl` and `websiteUrl` = `https://shbh-mirai.github.io/day-planner/`, `validDomains: ["shbh-mirai.github.io"]`, `webApplicationInfo.id` = `ce947e4a-b18a-4a3c-bf77-eb5811b6a3c8`.
- Git: commit per task; push and merge only after a green suite, as Shubh asked ("build it").

## Review Focus
1. In a browser, detection must time out quickly and fall back to the redirect flow. A slow fallback would delay every page load.
2. In Teams with no cached account, the app must show the sign-in button (popup), not a blank page.
3. "Sign in again" (expired token) inside Teams must use a popup. A redirect inside the Teams iframe would break.

### Task 3: Host-aware sign-in
